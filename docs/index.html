Listening

On device

Not a remote control. The whole agent.

Most mobile AI apps are a window into someone else's server. Pi Voice is different: the agent runs on the phone in your hand, with the same powers it has on a laptop.

  • It works where your code lives

    Pi runs in Termux with a real shell: it edits files, runs tests, installs packages and uses git, the GitHub CLI and SSH — on your phone.

  • Your model, your choice

    Use any provider Pi supports — or serve a local model with llama.cpp or Ollama right on the phone. Then your code and prompts never leave the device.

  • No server in between

    The app, its host and Pi talk over 127.0.0.1. No Pi Voice cloud, no account, no relay — and no one else's machine running your agent.

How it works

Three steps. No keyboard.

Pi already does the work on your phone. Pi Voice takes the typing out of it — and tells you when it's finished.

  1. 1

    Speak

    Tap the microphone and say what you want, in your own words. Android's speech recognition turns it into text.

  2. 2

    Review & send

    Check the transcript, fix a word if needed, attach a screenshot. Nothing goes to Pi until you tap Send.

  3. 3

    Pi does the work, on your phone

    Pi edits files, runs commands and pushes to GitHub right on your device. A chime tells you when it's done — or a notification, if you've left the app.

Features

Everything Pi does, in your pocket.

Live activity

See exactly what Pi is doing

Every tool call as it happens: the command, how long it took and its latest output. Watch the reply being written, and when you need the full picture, jump straight into Pi's terminal in Termux.

  • Live output from running commands
  • Failed steps stand out at a glance
  • One tap to Pi's real terminal
Parallel sessions

Run conversations side by side

Every new conversation gets its own Pi, so starting one never interrupts another — even mid-reply. Switch between them, see at a glance which one just finished, and close any of them without touching the rest.

  • Up to four sessions at once
  • Close any one, the others keep going
  • Background replies are flagged
Voice first

Built around your voice

Push to talk, check the transcript, and keep editing by hand when you want to. Nothing is sent until you tap Send — not by a misheard word, not by the Enter key. Replies can be read aloud on request; code blocks are skipped, so you hear the explanation, not the syntax.

  • Only the Send button sends
  • Read aloud in your language
  • Haptic feedback as you go

And the details you'd want.

Know when it's done

A chime and a light vibration while the app is open; a notification when it isn't. Tapping it opens that exact conversation.

Picks up where you left off

If Android stops Termux, opening the app brings back the conversation you had open. Pi sessions that survived are reattached as they were.

Show, don't describe

Attach up to four screenshots or photos for vision models. They're scaled and stripped of metadata on the phone.

Listen instead of reading

Have a finished reply read aloud with Android's text-to-speech. It never plays on its own.

Stays available

Manages Termux's wake lock so Pi keeps working while the screen is off, and reconnects with one tap if it stopped.

Feels like an app

A clean, dark interface with icon controls, bottom sheets and pull to refresh — not a terminal squeezed onto a phone.

Local by design

Private by architecture, not by promise.

The app talks to a small host in Termux over your phone's loopback interface, and the host talks to your Pi sessions. There is no Pi Voice server on the internet to trust, because there isn't one. Add a local model, and your code never leaves the phone at all.

  • The host and every session listen only on 127.0.0.1, behind a random 256-bit token.
  • Notifications are signed and tied to their conversation, so other apps can't fake them.
  • No account, no analytics, no telemetry. Pi Voice stores no audio.
  • Speech recognition uses Android's own service, which may process audio online — choose an offline voice if that matters to you.

Install

Up and running in a few minutes.

You need Android with Termux and a working Pi installation at ~/.pi/agent/bin/pi. Pi Voice adds the voice interface; it doesn't replace Pi.

  1. 1Add the extension in Termux

    Installs the bridge that lets the app talk to Pi. No npm install needed.

    pkg install git nodejs-lts util-linux tmux
git clone https://github.com/Endogen/pi-voice.git ~/pi-voice
cd ~/pi-voice
npm run setup

  2. 2Download the app

    Save the APK and its checksum to ~/pi-voice/native/out/, then check it with sha256sum -c pi-voice.apk.sha256.

    pi-voice.apk SHA-256 checksum All releases

  3. 3Install and allow

    Enables Termux's external-command setting (with a backup) and opens Android's installer. Then open Pi Voice and grant Run commands in Termux.

    cd ~/pi-voice
npm run native:install -- --enable

Heads-up: “Run commands in Termux” is a broad Android permission — only grant it to apps you trust. Pi Voice only ever runs its own fixed helper scripts. Prefer building it yourself? See the build guide.

FAQ

Questions, answered.

Something else? Open an issue on GitHub.

Does the agent really run on my phone?

Yes. Pi runs in Termux on your Android phone and works with the phone's own files and tools: it edits code, runs commands, installs packages and uses git and GitHub there. Only the language model can be elsewhere — at a provider of your choice, or on the phone too.

Can it run completely offline?

Yes, with a local model served by llama.cpp or Ollama in Termux, plus Android's offline speech recognition and voices. How fast and capable that is depends on your phone and the model size: small local models are quicker to run but less capable than large hosted ones.

Does Pi Voice work without Pi?

No. Pi Voice is an interface for the Pi coding agent. Pi must already be installed and configured with your model provider in Termux. Pi Voice adds voice input, notifications and a phone-friendly view on top.

Which phones does it support?

Android 8.0 or newer with Termux from GitHub or F-Droid and an up-to-date Android System WebView. It's developed on Android 16.

Why does it need “Run commands in Termux”?

That's how the app starts the Pi Voice host and your Pi sessions in the background without opening a terminal window, brings them back when Android stopped them, and opens a session's terminal when you ask. The app only runs its own fixed helper scripts and never accepts commands from other apps.

Will Android kill Pi in the background?

It can. Pi Voice holds Termux's wake lock while Pi runs, and you should set Termux's battery use to Unrestricted. If Android stops it anyway, opening the app restarts the host, reattaches any Pi sessions that survived and reopens the conversation you had open.

Does my voice leave the phone?

Speech recognition and text-to-speech use the services you've selected in Android, which may process audio online. Pi Voice itself records and stores no audio. Your messages go to your model provider through Pi, exactly like typed prompts.

Does it cost anything?

Pi Voice is free and its source is on GitHub. With a local model there are no API costs at all; with a hosted model, usage is billed by your provider, as with Pi alone.
